# Bluesky

**Bucket:** Native thread. Backlink in the final post only.

Bluesky's audience skews technical and link-tolerant compared to Twitter, but
the thread-then-link discipline still applies.

## Format

Same shape as the Twitter file — numbered blocks separated by blank lines:

```
1/
<hook post, ≤ 300 chars>

2/
<post, ≤ 300 chars>

...

N/
Full breakdown: <source_url>
```

## Length

≤ 300 characters per post (Bluesky's limit, slightly more generous than
Twitter). Links don't get auto-shortened — they count their full length. Plan
accordingly.

## Thread length

5–10 posts. Bluesky readers tolerate slightly longer threads than Twitter but
not dramatically.

## Hook

Same shapes as Twitter (contrarian, stat, curiosity gap, personal stake). Pull
from the source. No link, no hashtag.

## Images

Bluesky supports up to 4 images per post and the algorithm rewards them. If the
source has a hero image or relevant inline images, attach them to the hook post
or to body posts where they illustrate the point. Note in the output file which
post each image attaches to:

```
1/
<hook post>
[image: <URL from skeleton>]

2/
<post>
```

## Hashtags

0–1. Bluesky doesn't have a strong hashtag culture — they work but aren't
expected.

## Final post

```
N/
Full breakdown: <source_url>
```

## Backlink placement

Final post only.
